O que é o Git?

O Git é um sistema distribuído de controle de versões executado localmente na sua máquina. Ele cria registros pontuais (snapshots) do estado de cada arquivo do seu projeto, permitindo alternar entre versões, comparar linhas modificadas e criar ramificações paralelas com segurança.

O que é o GitHub?

O GitHub é uma plataforma online de hospedagem e colaboração para repositórios Git. Além de garantir backup na nuvem, ele permite publicar sites estáticos gratuitamente através do GitHub Pages, servindo HTML, CSS e JavaScript via HTTPS.

Sincronização Remota: Entenda as Diferenças Cruciais

LEITURA SEGURA git fetch

Busca atualizações do remoto sem integrar automaticamente. Ele baixa metadados e novos commits para você inspecionar antes de mesclar com seu código local.

INTEGRAÇÃO LOCAL git pull

Busca e integra alterações ao branch local. Equivale a um git fetch seguido imediatamente de um git merge, atualizando seu ambiente de trabalho.

ENVIO DEFINITIVO git push

Envia commits locais ao repositório remoto. Publica seu histórico salvo no GitHub, tornando suas alterações visíveis aos outros e disparando o deploy no Pages.

PASSO A PASSO PRÁTICO

Fluxo Completo de Trabalho no Dia a Dia.

O ciclo padrão executado por profissionais para desenvolver e versionar novas funcionalidades.

Passo 1: Manter a branch local sincronizada antes de começar SINCRONIZAÇÃO

Sempre atualize sua branch de trabalho principal antes de iniciar novas alterações para evitar divergências de histórico.

git switch main
git pull origin main
Passo 2: Criar e alternar para uma branch dedicada RAMIFICAÇÃO

Trabalhe de forma isolada sem correr o risco de quebrar o site principal em produção.

git switch -c feature/ajuste-design
Passo 3: Salvar alterações na branch VERSIONAMENTO

Verifique os arquivos alterados com status, prepare-os com add e registre com commit descritivo.

git status
git add .
git commit -m "style: atualiza cores e botoes"
Passo 4: Enviar alterações e integrar à branch principal DEPLOY / MERGE

Retorne para a branch main, mescle as alterações testadas e envie para o GitHub com push.

git switch main
git merge feature/ajuste-design
git push origin main

O que é o .gitignore?

Um arquivo de texto na raiz do projeto onde você lista arquivos ou pastas que não devem ser versionados pelo Git (como pastas de dependências node_modules/, logs temporários ou arquivos locais de IDE como .vscode/).

Resolvendo Conflitos

Conflitos ocorrem quando duas alterações afetam as mesmas linhas. O Git insere marcadores visuais (<<<<<<< e >>>>>>>). Abra o arquivo, escolha qual código manter, apague os marcadores, execute git add e faça o commit de resolução.

Proteção de Credenciais

Atenção máxima: Nunca adicione senhas, chaves de API secretas ou tokens pessoais em arquivos monitorados pelo Git. Uma vez feito o push para um repositório público no GitHub, essas credenciais ficam expostas a robôs e varreduras automatizadas.
